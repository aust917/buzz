# Developing this Buzz fork

Start with [AGENTS.md](../../AGENTS.md) for repository instructions. Choose one
reference for your task rather than reading this directory in full.

| Need | Reference |
| --- | --- |
| Find code, tests and subsystem boundaries | [Architecture](architecture.md) |
| Prepare an environment or select validation commands | [Development](development.md) |
| Implement a plugin or understand its hooks | [Plugin reference](plugins.md) |
| Structure an agent task, plan or handoff | [Agent workflow](agent-workflow.md) |
| Track upstream, understand fork scope and inherited release settings | [Fork maintenance](fork.md) |

These are engineering references. The Docusaurus application lives one level
up in `docs/`; its published user pages are in [docs/docs](../docs/).
Development references live outside that content directory.

Keep facts next to their owner: commands in the development guide, subsystem
boundaries in the architecture map, plugin examples in the plugin reference,
and short working constraints in scoped instructions. Source and configuration
files remain authoritative when a reference becomes stale.
